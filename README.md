# CloudMedia

本地影视资料库：从公开网站定时收集电影、电视剧和播放地址，在自己的页面中浏览、搜索和播放。影片信息保存在本地数据库，源站域名变更时可以修改采集入口。

[开发分支](https://github.com/oho-work/CloudMedia/tree/dev) · [Docker 部署](DOCKER.md) · [开发与贡献](CONTRIBUTING.md)

## 当前功能

- 影视库：片名、导演、演员搜索，类型、年份和来源筛选，影片详情与剧集、播放线路选择。
- 采集源：添加、编辑、启停、删除和手动采集，固定通过 CSS 选择器解析 HTML 页面。
- 自动更新：按配置时区每日采集已启用的源，保存任务状态、数量和错误信息。
- 采集范围：今天、全部、区间三种选择；区间提供起止日期选择器，分批入库并补齐各线路、剧集的播放地址。
- m3u8 检测：解析清单，选择高、低画质，抽样下载视频分片，记录分辨率、下载速度、耗时、下载字节数和检测时间。
- 本地播放：通过服务端代理 HLS 清单、分片和相关资源，处理常见的浏览器跨域限制。
- 图片永久归档：海报二进制与内容哈希、大小、来源、归档状态统一保存在 PostgreSQL。页面通过本站接口读取数据库图片；失败显示占位并后台重试，不回退源站图片。
- 资源历史：保存播放地址变更及每次取得的检测结果，包含分辨率、下载速度、抽样量、耗时和检测时间；旧测量不会因地址刷新而丢失。

**目前归档的是影片资料、海报及播放地址。m3u8 清单和视频分片仍从远端读取，没有全片下载或离线观影功能。** 源站变更后，本地资料继续保留；远端视频地址仍可能失效、过期或受访问限制。

## 环境与启动

推荐 **Node.js 24 LTS**，最低支持 Node.js 22.12。需要可访问的 PostgreSQL 数据库；本项目不会创建数据库本身，会在指定库中创建独立 schema。也可以直接使用 [Docker 部署](DOCKER.md)，无需在宿主机安装 Node.js。

获取仓库的 `dev` 分支：

```powershell
git clone --branch dev git@github.com:oho-work/CloudMedia.git
cd CloudMedia
git switch dev
npm ci
Copy-Item .env.example .env
```

克隆需要 GitHub SSH 访问权限。Linux/macOS 将 `Copy-Item .env.example .env` 换成 `cp .env.example .env`。已有工作区更新前，先确认本地修改，再执行 `git switch dev` 和 `git pull --ff-only origin dev`。

编辑 `.env`，填入自己的连接信息。以下仅为格式示例：

```dotenv
DATABASE_URL=postgresql://app_user:YOUR_URL_ENCODED_PASSWORD@db.example.com:5432/postgres
PGSCHEMA=cloudmedia
HOST=127.0.0.1
PORT=3001
APP_AUTH_TOKEN=
ALLOW_PRIVATE_UPSTREAM=false
```

连接用户名区分大小写。密码中的特殊字符需要进行 URL 编码，例如 `@` 写为 `%40`、`#` 写为 `%23`。连接用户需要目标 schema 的创建、读写权限。不要将实际密码写入 README、提交到 Git 或放入前端代码；`.env` 已被 `.gitignore` 排除。

完成配置后：

```powershell
npm run build
npm start
```

浏览器打开 [http://127.0.0.1:3001](http://127.0.0.1:3001)。默认只监听本机。更新代码后重新运行 `npm run build` 并重启服务。

Windows 可运行 `./start.ps1`：脚本检查 Node.js 版本，必要时使用当前 Codex 环境附带的 Node.js 24，安装缺少的依赖后构建并启动服务。该脚本不会覆盖已有 `.env`。保持服务进程运行，定时采集才会执行；当前未安装开机自启服务。

开发时可使用 `npm run dev`：前端为 [http://127.0.0.1:5173](http://127.0.0.1:5173)，API 为 `127.0.0.1:3001`，前端开发服务代理 `/api` 请求。

配置 `DATABASE_URL` 后，影片资料、播放资源、设置、任务和海报都写入 PostgreSQL，不再生成本地 JSON 数据文件或海报文件，也不自动生成本地备份。数据库连接或海报写入失败不会回退磁盘。未设置 `DATABASE_URL` 时，开发预览模式仅将资料写入 `DATA_FILE`，图片只保留在内存中，重启后重新获取。所有模式均不支持 `POSTER_DIR`，不会读取或生成项目图片目录；需要全部数据持久入库的部署必须配置数据库连接。

### 图片数据库归档与已有资料补存

PostgreSQL 模式将图片二进制存入 `poster_files` 表的 `BYTEA` 列，使用 `/media/posters/<内容哈希>.<扩展名>` 作为稳定地址，相同内容共享记录。支持 JPEG、PNG、WebP、AVIF 和 GIF，单张最多 4 MiB，先在内存中校验实际文件特征，再写入数据库，不经过本地临时文件。浏览图片时直接读取数据库，并支持 ETag 和浏览器缓存。

启动后后台检查已有影片，补存远程海报；数据库中缺少图片时，会使用已保存原图地址补下载，或从对应详情页恢复原图地址。找不到地址、网络失败或图片无效时记录原因并退避重试，影片简介与其他资料仍可查看。下载前保存原图来源，下载失败不会覆盖已有可用图片。打开“系统设置”的“图片归档”查看数量或点击“补存 / 重试图片”；只有图片成功入库才标记已归档。首次大量补存可能持续较长时间，请保持服务运行。

浏览列表及详情不再请求源站海报；播放器只有点击“播放视频”后才读取远端视频。查看分辨率与速度显示已保存的测量，不自动重新检测。重新解析地址、重新检测或更新资料仍需要访问对应上游；保存地址无法保证签名永不过期。

PostgreSQL 保存的是你自己的影视资料，与采集源站独立；若数据库部署在远程机器，浏览资料仍需要能连接该数据库。迁移到新机器只需使用相同数据库和 schema，不再需要应用机器上的图片目录。旧版的文件海报应先直接导入数据库并核验，再移除旧文件；运行时不会读取旧目录作为数据库故障回退。

## 第一次采集

1. 在“采集源”中添加或编辑源，确认入口域名、列表路径和 CSS 选择器。
2. 点击“立即采集”选择今天、全部或区间。555 默认取今天；区间需要选择开始和结束日期，适合分段补采。
3. 在“任务记录”查看扫描、新增、更新、资源数量及错误信息。
4. 在“影视库”打开影片，检查资料、剧集名称、播放线路和检测数据。
5. 验证配置后，在源卡片启用该源，设置默认范围和每日任务。

默认仅内置 555 影视，首次启动暂停，确认可访问后再启用。以下为 2026-11-03 检查结果，源站状态和页面结构可能变化：

| 入口 | 接入情况 |
| --- | --- |
| `https://www.555k03.com/` | 公开页面和播放器数据可解析，使用 HTML 适配；后续页面结构变化仍需调整配置。 |

程序不执行源站任意 JavaScript，也不处理验证码、登录绕过或 DRM 破解。请求保留间隔、有限重试和退避；遇到 401、403、人机验证时停止当前采集。实际内容及其权利属于相应提供方。

## 源配置说明

所有源固定使用 HTML / CSS 选择器解析，可设置请求间隔、并发数和默认采集范围。启用状态在源卡片上切换，编辑窗口不再重复显示。Referer 自动使用原列表、详情或播放页面，无需手动配置。请求间隔以秒设置，默认 2.5 秒，可填 0–60 秒，支持三位小数；0 表示请求之间不额外等待。数据库和 API 的 `requestIntervalMs` 继续按毫秒保存，已有 2500 毫秒配置显示为 2.5 秒。

请求间隔旁的“并发数”控制详情、播放地址解析及分辨率/速度检测的同时处理数量，可设为 1–20，默认 1。1 表示串行，设置为 3 时该源共用最多 3 个处理槽位；多影片、多集、手动检测和自动任务共用该源上限，不会按影片数相乘。列表翻页仍保持顺序，一次采集内的源站页面请求按设置间隔依次发起，0 秒时可直接填满并发槽位。已运行的任务固定使用提交时的并发设置，修改后用于下一次任务。同一条资源的检测与地址刷新依次执行，避免旧结果覆盖新地址。图片仍通过独立归档队列保存。

全部范围均不限制影片数、列表页数或每部影片的播放页数。采集到列表结束、没有下一页，或检测到已访问列表页形成循环时结束；同次任务对来源页面和影片链接去重。网络错误或访问受限仍可能停止任务。长任务可在“任务记录”查看每 4 秒更新的进度和已归档数量。

排队中或运行中的任务可在“任务记录”直接点击“取消”。排队任务立即中断，运行中的任务会中止当前请求后退出；状态可能短暂显示“取消中”，最终记录为“已中断”。已经保存的影片资料和资源会保留，取消不会删除采集结果；之后可再次手动采集。

### 今天、全部与区间

555 影视的 `/label/new.html` 是按更新时间倒序排列的全站列表，默认选择“今天”。编辑源可以保存默认范围，点击“立即采集”可以临时选择本次范围，不改变默认设置：

- **今天**：使用系统设置时区的当天日期（默认 `Asia/Shanghai`），忽略历史保存的起止日期。
- **全部**：遍历列表中的全部影片与播放资源，不按日期筛选。
- **区间**：使用日期选择器填写开始和结束日期，两端均包含；开始日期不能晚于结束日期。

任务创建后日期和时区固定，跨午夜不会改变正在采集的范围。定时任务使用源保存的默认范围。

按日期采集时逐页读取详情中的“更新”日期，跳过区间之后的影片，在有序列表遇到区间之前的影片时结束。每批先把影片资料保存到已配置的数据库，立即读取该批各线路、各集的公开播放地址并保存，再继续下一批，不再等待整个日期范围的资料扫描完毕。批次大小由并发数控制；过程中每五个播放页以及影片结束或中断时保存检查点。当前批次尚未取得片源或任务中断时，可能暂时出现 0 资源；未匹配到播放链接、解析不到地址及请求失败都会记录错误。重新采集会复用有效缓存并补齐缺失资源。任务记录显示范围、进度、新增/更新数量与错误。

源站的日期是影片**当前最后更新日期**，不是历史变更日志；已经再次更新的影片无法还原过去某天的版本。列表在采集期间变化时会去重，但无法提供同一时刻的全站快照。全线路、全剧集可能需要数小时或更久，请保持服务和数据库运行。保存的是影片资料与播放地址，远端视频文件不在本次归档范围内。

接口也支持相同操作：`POST /api/sources/:id/run`。空请求体使用源的默认范围，显式选择可发送 `{"mode":"today"}`、`{"mode":"all"}` 或 `{"mode":"range","startDate":"2026-11-01","endDate":"2026-11-03"}`。区间需要有效的 `YYYY-MM-DD` 起止日期，未传日期时可使用源保存的完整区间；兼容旧版不带 `mode` 的日期请求，单个日期按单日处理。同一源已有相同范围任务时复用，不同范围返回 `409`，可先取消旧任务。

今天和区间需要 HTML 详情页中可识别的“更新/更新时间”日期。“列表按更新时间倒序”只应在确认顺序后启用，关闭时会遍历整个列表筛选日期。

### HTML 页面

列表路径相对于“网站入口”解析，例如 `/`。配置 CSS 选择器以适应站点结构：

| 配置 | 用途与示例 |
| --- | --- |
| 详情链接选择器 | 从列表取得影片详情页，例如 `a[href*="/voddetail/"]`。 |
| 标题选择器 | 从详情页取得片名，例如 `h1`。 |
| 海报、简介选择器 | 对应详情页中的海报元素和简介区域。 |
| 播放链接选择器 | 取得直接 m3u8 链接或播放页，例如 `a[href*="/vodplay/"]`。 |
| 下一页选择器 | 查找列表下一页链接，例如 `a[title="下一页"]`。 |

播放页仅解析直接公开的 m3u8 地址和常见 `player_*` JSON 字面量中的播放地址。需要执行脚本、专用解析服务或其他交互才能取得地址的站点不保证支持。

采集会复用未过期的已采集播放页，并优先读取未知播放页。有明确集数、日期或期号时，优先读取最新未收录的剧集，再补齐旧集；没有可靠序号的正片、预告等保留页面顺序。缓存过期，或对应资源上一次检测失败时，会重新读取播放页以更新地址。“系统设置”中的 `resourceRefreshHours` 控制缓存时长，默认 168 小时（7 天），范围 1–720 小时；这只缓存播放页解析得到的地址，不缓存视频内容。

### 域名变化

直接编辑原有源的“网站入口”，保留源 ID。系统保留影片和资源记录，更新对应的影片来源页面地址；视频 CDN 地址保留原值，避免将独立 CDN 域名误替换为新站域名。之后重新采集可更新已发现的播放地址。

删除采集源也会保留已归档影片和播放资源；正在运行或排队的源需先等待任务结束。

## 定时更新与资源检测

“系统设置”默认每天 **Asia/Shanghai 时区 03:00** 运行。服务必须持续运行才能执行任务；关闭应用不会由操作系统替它执行。程序每 30 秒检查一次，到指定时间后为当日尚无相同默认范围任务的已启用源创建任务；当日错过时间后重启，会进行当天检查，不追补所有历史日期。手动采集不同范围不会占用默认范围的定时名额。同一源正在运行或排队时不会再创建任务；失败或取消后可手动重试。

资源缓存与测速参数：

| 参数 | 作用 |
| --- | --- |
| `resourceRefreshHours` | 播放页地址缓存多久后重新读取，默认 168 小时；上次资源检测失败的播放页会提前刷新。 |
| `sampleSegments` | 检测每条资源时抽测多少个视频分片，默认 1，后台可设 1–10。 |
| `sampleBytes` | 页面以 MB 设置每个抽测分片的下载上限，1 MB = 1,000,000 字节；默认 0.262144 MB（262144 字节）。API 和数据库继续保存字节数。 |
| `preferredQuality` | 多画质清单中选择最高或最低画质进行检测。 |
| `probeTimeoutMs` | 页面以秒设置单次检测请求超时，默认 15 秒；API 和数据库继续保存毫秒数。 |

User-Agent 默认使用 Chrome Stable 桌面版 UA（截至 2026-11-04 核验为 Chrome 157；Chrome 的版本缩减规则使用 `Chrome/157.0.0.0`）。已有内置旧 UA 会自动更新，手动设置的自定义 UA 会保留。

**Mbps 是采集服务器到远端播放源/CDN 的样本下载速度，不是观众设备的网速，也不是视频声明的码率。** 小样本结果会受到连接建立、源站状态及网络波动影响；系统保留样本字节数、耗时和检测时间供判断。没有足够可靠的信息时，分辨率显示“未知”，不会根据速度猜测分辨率。

采集后自动检测默认开启，主要检测新发现或地址变化的资源。已有资源可以在影片详情中手动重新检测。保存了原播放页且采集源仍存在时，还可点击“重新解析地址”：重新请求原播放页取得地址、再次检测并重新加载播放器；“检测当前资源”只检测已保存的地址，不会重新获取过期地址。清单中缺少分辨率时会尝试从支持的未加密视频样本提取；部分加密、编码格式或样本不足的资源可能可播放但无法识别尺寸。fMP4 在需要时还会额外读取一个受限的初始化分片以识别尺寸。

服务重启后，未完成的采集任务标记为“已中断”，可手动重新采集；不会假定此前任务已完成。

## 局域网访问

需要其他设备访问时，在 `.env` 中设置：

```dotenv
HOST=0.0.0.0
APP_AUTH_TOKEN=REPLACE_WITH_A_LONG_RANDOM_TOKEN
```

重启后通过运行本程序的机器的局域网 IP 和 `3001` 端口访问。首次连接需在页面输入令牌；令牌保存在该浏览器的本地存储中。未设置令牌时，程序拒绝监听非本机地址。

只在受控网络开放相应端口。跨不可信网络访问时，使用 HTTPS 反向代理或 VPN；当前没有多用户账号、用户隔离和权限角色。上游请求默认拒绝私网及回环目标，`ALLOW_PRIVATE_UPSTREAM=true` 仅用于确实需要访问自有私网内容源的部署或开发测试。

## 存储与容量边界

PostgreSQL 的 `cloudmedia` schema 下，`movies`、`resources`、`sources`、`runs` 和 `settings` 采用 `id + JSONB` 记录，`poster_files` 保存图片二进制及校验元数据。应用启动后将目录读入进程内缓存，图片按请求读取数据库；搜索、筛选和分页在应用中完成，写入按顺序持久化。单个 schema 同时只允许一个实例运行；这是本地应用起步版，尚不是面向海量数据的分布式查询或采集平台。

数据规模、并发和任务量增加后，需要将检索和分页下推为 SQL、设计更细化的关系表与索引，拆分持久任务队列和采集 worker，再考虑多进程和多节点运行。目前不依赖 Redis、MySQL 或 MongoDB。

应用不自动生成数据库转储、JSON 快照或本地图片副本。数据库本身的数据保护和迁移由数据库管理员安排；迁移时需要包含 `poster_files`，并在变更前停止应用以释放 schema 锁。数据库中不包含远端视频文件，也无法保证远端播放地址以后仍然有效。

## 验证与项目结构

```powershell
npm run typecheck
npm test
npm run build
```

`web/` 是 React 管理和观影界面，`server/` 包含 API、采集、检测、代理、任务和存储实现，`shared/` 保存数据类型，`tests/` 为采集解析、HLS 和目录行为测试。`dist/` 是前端构建产物，`data/` 和 `.env` 均不提交 Git。

仓库只包含应用源码、锁定的依赖清单、示例配置和文档。实际采集记录、海报、数据库备份、访问令牌和个人运行配置应保存在自己的部署环境。开发约定和提交前检查见 [CONTRIBUTING.md](CONTRIBUTING.md)。
