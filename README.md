# CloudMedia

本地影视资料库：从公开网站定时收集电影、电视剧和播放地址，在自己的页面中浏览、搜索和播放。影片信息保存在本地数据库，源站域名变更时可以修改采集入口。

[开发分支](https://github.com/oho-work/CloudMedia/tree/dev) · [Docker 部署](DOCKER.md) · [开发与贡献](CONTRIBUTING.md)

## 当前功能

- 影视库：片名、导演、演员搜索，类型、年份和来源筛选，影片详情与剧集、播放线路选择。
- 采集源：添加、编辑、启停、删除和手动采集，支持 HTML 页面、MacCMS JSON API、通用 JSON API。
- 自动更新：按配置时区每日采集已启用的源，保存任务状态、数量和错误信息。
- 日期采集：555 影视默认只取今天，可指定包含起止日期的区间，分批入库并补齐各线路、剧集的播放地址。
- m3u8 检测：解析清单，选择高、低画质，抽样下载视频分片，记录分辨率、下载速度、耗时、下载字节数和检测时间。
- 本地播放：通过服务端代理 HLS 清单、分片和相关资源，处理常见的浏览器跨域限制。
- 海报缓存：成功取得的海报保存在 `data/posters`；下载失败时保留远端海报地址，不阻塞影片信息入库。

**目前归档的是影片资料、海报及播放地址。m3u8 清单和视频分片仍从远端读取，没有全片下载或离线观影功能。** 源站变更后，本地资料继续保留；远端视频地址仍可能失效、过期或受访问限制。

## 环境与启动

推荐 **Node.js 24 LTS**，最低支持 Node.js 22.12。需要可访问的 PostgreSQL 数据库；本项目不会创建数据库本身，会在指定库中创建独立 schema。也可以直接使用 [Docker 部署](DOCKER.md)，无需在宿主机安装 Node.js。

获取仓库的 `dev` 分支：

```powershell
git clone --branch dev git@github.com:oho-work/CloudMedia.git
cd CloudMedia
git switch dev
npm ci
Copy-Item .env.example .env
```

克隆需要 GitHub SSH 访问权限。Linux/macOS 将 `Copy-Item .env.example .env` 换成 `cp .env.example .env`。已有工作区更新前，先确认本地修改，再执行 `git switch dev` 和 `git pull --ff-only origin dev`。

编辑 `.env`，填入自己的连接信息。以下仅为格式示例：

```dotenv
DATABASE_URL=postgresql://app_user:YOUR_URL_ENCODED_PASSWORD@db.example.com:5432/postgres
PGSCHEMA=cloudmedia
HOST=127.0.0.1
PORT=3001
APP_AUTH_TOKEN=
ALLOW_PRIVATE_UPSTREAM=false
DATA_FILE=./data/cloudmedia.json
```

连接用户名区分大小写。密码中的特殊字符需要进行 URL 编码，例如 `@` 写为 `%40`、`#` 写为 `%23`。连接用户需要目标 schema 的创建、读写权限。不要将实际密码写入 README、提交到 Git 或放入前端代码；`.env` 已被 `.gitignore` 排除。

完成配置后：

```powershell
npm run build
npm start
```

浏览器打开 [http://127.0.0.1:3001](http://127.0.0.1:3001)。默认只监听本机。更新代码后重新运行 `npm run build` 并重启服务。

Windows 可运行 `./start.ps1`：脚本检查 Node.js 版本，必要时使用当前 Codex 环境附带的 Node.js 24，安装缺少的依赖后构建并启动服务。该脚本不会覆盖已有 `.env`。保持服务进程运行，定时采集才会执行；当前未安装开机自启服务。

开发时可使用 `npm run dev`：前端为 [http://127.0.0.1:5173](http://127.0.0.1:5173)，API 为 `127.0.0.1:3001`，前端开发服务代理 `/api` 请求。

未设置 `DATABASE_URL` 时，系统明确进入本地 JSON 文件预览模式，数据写入 `DATA_FILE`。设置了连接但数据库无法连接时，系统停止启动，不会自动切换到文件模式。配置 PostgreSQL 后，文件模式中已有的数据不会自动迁入数据库。

## 第一次采集

1. 在“采集源”中添加或编辑源，确认入口域名、列表路径和解析方式。
2. 普通列表模式先设置较小的上限，例如 1 页、2 部影片，再使用“立即采集”检查结果。555 的日期模式默认取今天，数量上限不生效；可按需选择其他日期区间。
3. 在“任务记录”查看扫描、新增、更新、资源数量及错误信息。
4. 在“影视库”打开影片，检查资料、剧集名称、播放线路和检测数据。
5. 验证配置后启用该源，调整采集规模和每日任务。

内置两个入口，首次启动均暂停，确认可访问后再启用。以下为 2026-11-03 检查结果，源站状态和页面结构可能变化：

| 入口 | 接入情况 |
| --- | --- |
| `https://www.555k03.com/` | 公开页面和播放器数据可解析，使用 HTML 适配；后续页面结构变化仍需调整配置。 |
| `https://m.zc0577.com/` | 检查时返回人机验证页面，保持停用；采集器遇到此类页面会停止并记录原因。 |

程序不执行源站任意 JavaScript，也不处理验证码、登录绕过或 DRM 破解。通过请求间隔、有限重试、退避和可选 robots.txt 规则控制访问；遇到 401、403、人机验证时停止当前采集。应使用自己获准访问、采集和播放的内容源，实际内容及其权利属于相应提供方。

## 源配置说明

所有源均可设置请求间隔、最多页数、最多影片数、Referer 和启用状态。新建源默认最多 2 页、30 部影片、每部影片每次最多新请求 30 个播放页；这三个上限均可设为 **0，表示不限**，正数须为安全整数。请求间隔默认 2500 毫秒；多部影片和剧集按顺序处理，避免同一时刻大量请求。

不限模式只取消数量上限，仍遵守访问间隔、robots.txt 配置及网络错误处理。采集到列表结束、没有可继续读取的下一页，或检测到已访问列表页形成循环时结束；同次任务对来源页面和影片链接去重，避免反复请求同一页面。JSON 接口还参考空列表和接口返回的分页信息结束。请求失败或访问受限仍可能停止任务，因此“不限”不代表站点所有内容已成功归档。不限模式可能耗时较长，可在“任务记录”查看每 4 秒更新的当前处理信息和已归档数量。

排队中或运行中的任务可在“任务记录”直接点击“取消”。排队任务立即中断，运行中的任务会中止当前请求后退出；状态可能短暂显示“取消中”，最终记录为“已中断”。已经保存的影片资料和资源会保留，取消不会删除采集结果；之后可再次手动采集。

### 555 影视今日更新与日期补采

555 影视的 `/label/new.html` 实际是按更新时间倒序排列的全站列表。内置此源默认使用“按更新日期”模式，点击“立即采集”选择日期，默认是系统设置时区的今天（默认 `Asia/Shanghai`），也可以选择包含起止日期的区间。任务创建后日期和时区固定，跨午夜不会改变正在采集的范围。定时任务也默认只取当天。

此模式自动取消页数、影片数和每部影片播放页的数量上限：逐页读取详情中的“更新”日期，跳过区间之后的影片，在有序列表遇到区间之前的影片时结束。先把范围内影片资料全部分批保存到已配置的数据库，再读取各线路、各集的公开播放地址，过程中每五个播放页以及影片结束或中断时保存检查点。资源失败会记录错误，任务不会将未取得地址的情况标为全部成功；重新采集会复用有效缓存并补齐缺失资源。任务记录显示范围、进度、新增/更新数量与错误。

源站的日期是影片**当前最后更新日期**，不是历史变更日志；已经再次更新的影片无法还原过去某天的版本。列表在采集期间变化时会去重，但无法提供同一时刻的全站快照。全线路、全剧集可能需要数小时或更久，请保持服务和数据库运行。保存的是影片资料与播放地址，远端视频文件不在本次归档范围内。

接口也支持相同操作：`POST /api/sources/:id/run`，空请求体默认今天，或发送 `{"startDate":"2026-11-01","endDate":"2026-11-03"}`。日期必须为有效的 `YYYY-MM-DD`；只提供一个日期时按单日处理。同一源已有其他日期范围任务时返回 `409`，可先取消旧任务；未开启日期模式的源不接受日期参数。

其他 HTML 源可以在编辑中选择“按更新日期”，需在详情中提供可识别的“更新/更新时间”日期。“列表按更新时间倒序”只应在确认顺序后启用；关闭时会遍历整个列表筛选日期。普通列表模式仍遵守配置的数量上限。

### HTML 页面

列表路径相对于“网站入口”解析，例如 `/`。配置 CSS 选择器以适应站点结构：

| 配置 | 用途与示例 |
| --- | --- |
| 详情链接选择器 | 从列表取得影片详情页，例如 `a[href*="/voddetail/"]`。 |
| 标题选择器 | 从详情页取得片名，例如 `h1`。 |
| 海报、简介选择器 | 对应详情页中的海报元素和简介区域。 |
| 播放链接选择器 | 取得直接 m3u8 链接或播放页，例如 `a[href*="/vodplay/"]`。 |
| 下一页选择器 | 查找列表下一页链接，例如 `a[title="下一页"]`。 |
| 每部影片每次最多新请求的播放页 | `maxResourcePages`，默认 30；0 表示不限，正数限制单次采集为每部影片新请求的播放页数量。已缓存的播放页直接复用，不计入此上限。 |

播放页仅解析直接公开的 m3u8 地址和常见 `player_*` JSON 字面量中的播放地址。需要执行脚本、专用解析服务或其他交互才能取得地址的站点不保证支持。

采集会复用未过期的已采集播放页，并优先读取未知播放页。有明确集数、日期或期号时，优先读取最新未收录的剧集，再逐次补齐旧集；没有可靠序号的正片、预告等保留页面顺序。长剧即使超过单次播放页请求上限，也可通过多次采集逐步补齐剧集，不会因为缓存资源数量达到上限而停止补充。缓存过期，或对应资源上一次检测失败时，会重新读取播放页以更新地址。“系统设置”中的 `resourceRefreshHours` 控制缓存时长，默认 168 小时（7 天），范围 1–720 小时；这只缓存播放页解析得到的地址，不缓存视频内容。

### MacCMS JSON API

列表路径通常为 `/api.php/provide/vod/`。适配器请求 `ac=detail`，通过 `pg` 翻页，并读取常见的 `vod_name`、`vod_play_from`、`vod_play_url` 等字段。支持 `$$$` 分隔线路、`#` 分隔剧集的常见资源格式。当前适配针对 JSON 接口，不支持 XML 接口。

### 通用 JSON API

配置数组所在路径，例如 `data.list`，以及片名字段、资源 URL 字段，字段路径支持点号。资源字段可以是 m3u8 字符串、常见的剧集拼接格式，或带 `url`、`name`、`episode` 的资源数组。其他影片字段识别常见英文或 MacCMS 字段。

通用接口第二页起使用 `page` 参数，并参考 `next`、`nextPage`、`pagecount` 判断分页。复杂游标、签名接口或自定义协议需要扩展适配器。

### 域名变化

直接编辑原有源的“网站入口”，保留源 ID。系统保留影片和资源记录，更新对应的影片来源页面地址；视频 CDN 地址保留原值，避免将独立 CDN 域名误替换为新站域名。之后重新采集可更新已发现的播放地址。

删除采集源也会保留已归档影片和播放资源；正在运行或排队的源需先等待任务结束。

## 定时更新与资源检测

“系统设置”默认每天 **Asia/Shanghai 时区 03:00** 运行。服务必须持续运行才能执行任务；关闭应用不会由操作系统替它执行。程序每 30 秒检查一次，到指定时间后为当日尚无任务的已启用源创建任务；当日错过时间后重启，会进行当天检查，不追补所有历史日期。按日期模式中，当天创建且包含当天日期的任务会占用当天定时名额，补采其他日期不占用该名额。同一源正在运行或排队时不会再创建任务；失败或取消后可手动重试。

测速参数与源的播放页上限作用不同：

| 参数 | 作用 |
| --- | --- |
| `maxResourcePages` | 每部影片每次最多新请求多少个播放页；0 表示不限。已有地址缓存不计入上限，可多次补齐剧集。 |
| `resourceRefreshHours` | 播放页地址缓存多久后重新读取，默认 168 小时；上次资源检测失败的播放页会提前刷新。 |
| `sampleSegments` | 检测每条资源时抽测多少个视频分片，默认 1，后台可设 1–10。 |
| `sampleBytes` | 每个抽测分片最多读取的字节数，默认 262144 字节，即 256 KiB。 |
| `preferredQuality` | 多画质清单中选择最高或最低画质进行检测。 |
| `probeTimeoutMs` | 单次检测请求的超时。 |

**Mbps 是采集服务器到远端播放源/CDN 的样本下载速度，不是观众设备的网速，也不是视频声明的码率。** 小样本结果会受到连接建立、源站状态及网络波动影响；系统保留样本字节数、耗时和检测时间供判断。没有足够可靠的信息时，分辨率显示“未知”，不会根据速度猜测分辨率。

采集后自动检测默认开启，主要检测新发现或地址变化的资源。已有资源可以在影片详情中手动重新检测。保存了原播放页且采集源仍存在时，还可点击“重新解析地址”：重新请求原播放页取得地址、再次检测并重新加载播放器；“检测当前资源”只检测已保存的地址，不会重新获取过期地址。清单中缺少分辨率时会尝试从支持的未加密视频样本提取；部分加密、编码格式或样本不足的资源可能可播放但无法识别尺寸。fMP4 在需要时还会额外读取一个受限的初始化分片以识别尺寸。

服务重启后，未完成的采集任务标记为“已中断”，可手动重新采集；不会假定此前任务已完成。

## 局域网访问

需要其他设备访问时，在 `.env` 中设置：

```dotenv
HOST=0.0.0.0
APP_AUTH_TOKEN=REPLACE_WITH_A_LONG_RANDOM_TOKEN
```

重启后通过运行本程序的机器的局域网 IP 和 `3001` 端口访问。首次连接需在页面输入令牌；令牌保存在该浏览器的本地存储中。未设置令牌时，程序拒绝监听非本机地址。

只在受控网络开放相应端口。跨不可信网络访问时，使用 HTTPS 反向代理或 VPN；当前没有多用户账号、用户隔离和权限角色。上游请求默认拒绝私网及回环目标，`ALLOW_PRIVATE_UPSTREAM=true` 仅用于确实需要访问自有私网内容源的部署或开发测试。

## 存储、备份与容量边界

PostgreSQL 的 `cloudmedia` schema 下保存 `movies`、`resources`、`sources`、`runs` 和 `settings`，目前采用 `id + JSONB` 记录。应用启动后将目录读入进程内缓存，搜索、筛选和分页在应用中完成，写入按顺序持久化。单个 schema 同时只允许一个实例运行；这是本地应用起步版，尚不是面向海量数据的分布式查询或采集平台。

数据规模、并发和任务量增加后，需要将检索和分页下推为 SQL、设计更细化的关系表与索引，拆分持久任务队列和采集 worker，再考虑多进程和多节点运行。目前不依赖 Redis、MySQL 或 MongoDB。

建议同时备份：

- PostgreSQL 中的项目 schema，例如使用 `pg_dump -h db.example.com -p 5432 -U app_user -d postgres -n cloudmedia -Fc -f cloudmedia.dump`。使用实际数据库地址和用户，密码通过 PostgreSQL 的安全凭据方式提供。
- `data/posters`，或设置了 `POSTER_DIR` 后的对应目录。仅备份数据库不能恢复本地海报文件。
- 本地文件模式下的 `data/cloudmedia.json`，或 `DATA_FILE` 指定的路径。
- 单独妥善保存运行配置和 `.env`，避免将凭据混入公开备份。

恢复时先停止服务，在目标库中恢复 schema 与海报目录，再启动应用。备份不包含远端视频文件，也无法保证远端地址以后仍然有效。

## 验证与项目结构

```powershell
npm run typecheck
npm test
npm run build
```

`web/` 是 React 管理和观影界面，`server/` 包含 API、采集、检测、代理、任务和存储实现，`shared/` 保存数据类型，`tests/` 为采集解析、HLS 和目录行为测试。`dist/` 是前端构建产物，`data/` 和 `.env` 均不提交 Git。

仓库只包含应用源码、锁定的依赖清单、示例配置和文档。实际采集记录、海报、数据库备份、访问令牌和个人运行配置应保存在自己的部署环境。开发约定和提交前检查见 [CONTRIBUTING.md](CONTRIBUTING.md)。
