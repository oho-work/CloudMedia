# 播放时检测与影视库筛选

用户要求采集并发最大 100；采集只保存资料、海报和片源，不检测视频速度与分辨率。只有点击播放某一集时才立即检测同一影片、同一集在所有线路中的资源。检测在后台执行，不能延迟播放器启动；结果保存在原资源记录中。移除独立测速按钮、整片检测入口和“采集后自动检测”开关。地址重新解析只更新地址。

同集匹配保守规范化第01集、第1集、EP01与纯数字标签；不同季、上下部、预告与花絮不得混并。同集不同线路并行检测，继续受已有同源并发限制；同一资源的重复播放检查复用执行中的检测，单条线路失败不取消其他线路。保留历史测量。采样大小、超时和清晰度设置继续用于播放检查。

影视库每页 12 部影片。用户确认类型、题材、地区、年份、更新状态、有无片源筛选；子标题显示全部、电影、电视剧、动漫、短剧、综艺分类。类型页签和条件筛选使用同一状态。改变条件回到第一页，清空可恢复全部数据；所有筛选先于分页，选项从完整资料库生成。卡片显示海报、片名、年份地区、更新状态和资源数量，桌面及移动布局适配。

实现选择：沿用 TypeScript、Express、React 与 PostgreSQL，不引入新依赖。新增 POST /api/resources/:id/check-playback，响应 { resources: Resource[] }，前端与视频播放同时发起请求并在完成后更新各线路数据；不因查看详情发起检测。影视库查询抽成独立纯模块，短剧分类兼容已保存的题材信息。原有采集源、图片数据库存储与定时策略继续使用。

验证：真实本地 HTTP 证明采集期间没有视频清单/分片测量、播放检查只涉及同集线路且不串集、100 并发边界、组合筛选和分页正确；旧功能测试按新行为更新，完成全套测试、构建和页面检查。运行变更后重启服务，中文提交到本地 dev；此次未要求推送。
