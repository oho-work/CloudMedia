# 影视资料与图片永久归档

用户已确认：保留现有 PostgreSQL，图片以普通文件永久保存到运行 CloudMedia 的部署机器磁盘，不存入数据库二进制字段。除视频播放内容外，已取得的影片资料、图片、资源地址、分辨率、速度和检测信息不依赖原采集站展示。

## 存储约定

- 影片资料和图片归档信息仍写入现有 PostgreSQL JSONB；不增加本机离线数据库副本。
- 图片默认保存至 `data/posters`，允许 `POSTER_DIR` 指定永久卷目录；文件名使用图片内容 SHA-256 与验证后的图片扩展名。相同图片共享文件。
- 数据库保存原图地址、来源页、实际文件地址、哈希、格式、大小、下载时间、尝试次数、错误与下次重试时间。原图地址只用于后台补归档，浏览器只请求本站图片。
- 下载失败保留归档状态并退避重试，显示本地占位；不回退远程图片，不覆盖已成功归档文件。缺少原图地址的旧本地图片记录尝试从已保存的原详情页恢复图片地址，无法恢复则明确标记缺失。
- 兼容现有 URL 哈希命名的图片，验证文件存在及实际格式。图片响应有界下载、原子落盘，拒绝 HTML、空文件和超过 4 MiB 的内容。

## 数据与运行

- 已存影片后台分批检查和补存，不阻塞 HTTP 启动；单队列、每个图片主机至少 1 秒间隔，停止服务取消下载并保存已完成进度。
- 采集的元数据先保存；普通采集完成前尝试归档海报，失败不丢影片及资源。日期采集检查点同样保留原图来源。
- 保留资源地址变更记录和检测历史；旧资料当前检测及地址在后续处理时一并留档。浏览列表与详情不自动探测资源，只有点击播放、检测或重新解析时请求视频或源站。
- 设置页显示图片归档数量并提供补存/重试操作。缺失图片返回 404，不使用 SPA HTML 回退。
- PostgreSQL 加载时建立已持久化快照，避免每次启动重复写入全部未变化记录；真实的来源补全和中断任务仍保存。
- 备份和迁移需要同时保留 PostgreSQL schema 与图片目录；远端视频不下载、不做离线播放承诺。签名地址仍可能过期，既有快照不因此删除。

## 验证与交付

真实临时 HTTP/文件夹测试图片归档、源站停止后读取、去重、无效/过大图片、失败重试、缺失恢复；API 测试无远程回退及静态 404；隔离数据库边界测试启动持久化。运行完整测试、类型检查和构建，再重启实际服务，核对 PostgreSQL 健康与图片归档进度。中文 Git 提交，不提交凭据或实际归档数据。
